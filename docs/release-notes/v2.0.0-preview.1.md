# OES Enterprise v2.0.0-preview.1 — preview (2026-10-28)

The first release after the alpha. The 1.x line, last released as [v1.3.0](v1.3.0.md) on 2026-05-12, proved the
platform; 2.0 changes what it stands on. The designer and the client are thin now: they work against the server
over the platform's own protocol, and the desktop programs of 1.x are gone. The engine carries its own string,
value and variant types instead of the toolkit's, and builds as C++20 with wxWidgets 3.3.4 on Windows, Linux and
macOS. "Preview" names the road to beta: the database format may still change, and nothing migrates from 1.x.

## Breaking changes

- **License.** Since 2026-08-23 the platform is under PolyForm Noncommercial 1.0.0: source-available, free for
  noncommercial use; commercial use takes a separate license ([LICENSE.md](../../LICENSE.md)). The 1.x line was
  published under GNU LGPL 2.1.
- **Thin programs only.** The thick designer and client are removed. `designer-thin` and `enterprise-thin` work
  through a server; a 1.x program cannot connect to a 2.0 server.
- **No 1.x configurations.** The compatibility ladder starts again at 2.0.0; configurations and bases made by 1.x
  are not carried over.

## What the 2.0 line is made of

- **Thin designer and client** — metadata, forms, modules and the debugger, all against the server, on the
  platform's own protocol (OES-RPC 1.0), with TLS (`oess://`).
- **Browser client** — the same forms in a browser, served by the platform's web server.
- **Application server and cluster** — several servers to a base, a client routed back to its session, a tray to
  run them.
- **Data model** — catalogs, documents, information, accumulation, accounting and calculation registers, charts of
  accounts, of characteristic types and of calculation types; row-level access policies.
- **Queries** — the query language with a visual constructor, run on Firebird, PostgreSQL, SQLite or ODBC, or in
  memory.
- **Reports** — data composition, cross-tables and totals; spreadsheet documents read and written as Excel,
  written as Word.
- **Script language** — compiled to bytecode with an ahead-of-time cache; LINQ, lambdas and closures; HTTP, HTTPS
  and JSON built in.
- **MCP server** — an AI assistant reads and changes a configuration and runs code through the same sessions and
  rights as a person.

## Toolchain

- The engine and wxWidgets build as C++20, MSVC under strict conformance ([portability.md § 1.11](../portability.md)).
  On the `.sln` road the prebuilt wxWidgets binaries still link — MSVC's ABI does not change with the standard — and
  are rebuilt as C++20 by copying `build\msw\cxx20.props` to `wx_local.props`
  ([BUILD.md](../BUILD.md#wxwidgets-submodule-details)).
- wxWidgets moves from 3.3.2 to 3.3.4: a crash in the Edge backend of wxWebView fixed, Esc that IME or
  auto-completion used no longer closes the dialog (Windows), wxGrid crashes on changing the editor fixed,
  dark-mode fixes, wx's third-party libraries (png, expat, tiff, pcre) updated. Under GTK and macOS the module
  editor (wxStyledTextCtrl) now composes IME input inline.

## Status and known limits

- A pre-release. Before beta the database, metadata and protocol formats may change; a base made with this preview
  may have to be made again.
- No migration from 1.x.
- An old binary on the same base still acquires `sys_lock` without the `sys_lock_key` header row. Until every
  process is upgraded, two processes — one of them not upgraded — can both be granted the same key.
- The macOS package is not signed: macOS asks for confirmation on its first launch.
- Interface languages: English, Russian, Ukrainian.
- Problems and questions: [GitHub issues](https://github.com/open-enterprise-solutions/enterprise/issues).
