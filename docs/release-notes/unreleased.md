# Unreleased

A table read anew with no row to read around — a client's first page, a list read again from its top — is placed by the server: from the top when the table stands on no row, else around the row it stands on, with as many rows ahead of that row as the page, the page saying how many came (`Before`). The browser client took such a page for the top: a table standing on its last row came back to a resumed session as that one row, with no way to the rows above it. The thin client puts the row it was read around mid-view and reads the rows above the ones that came when there are more.

The browser client's table reads nothing while it has no height (a notebook page behind another), where every page fell short of the window and the whole list was read; and when the rows held fall short of the window with nothing after them, it reads back, not on.
