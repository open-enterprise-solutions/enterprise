## Main arc — journal-style audit log

### Backend (`src/engine/backend/logger/`, new directory)

Nine files implementing a local-SQLite audit log for the
"Журнал регистрации" admin surface:

* `loggerEntry.h` — `ibLogEntry` POD: ts_ms, level (Info/Warn/Error/Audit),
  session_id, user_name, host, source, event_type, message, **ref_guid**,
  **ref_meta_id**, details (BLOB, currently unused).
* `loggerQueue.{h,cpp}` — MPSC bounded queue (`std::mutex` +
  `std::condition_variable` + `std::deque`). `Push` drops new on overflow
  and increments a counter. `notify_one()` only on empty→non-empty
  transition (avoids one syscall per producer call under load).
* `loggerSink.h` — abstract destination (`WriteBatch`, `Flush`).
* `loggerSinkSqlite.{h,cpp}` — own `ibDatabaseLayerSQLite` connection
  (NOT in the main connection pool). Files `oes_YYYY_MM.olg`, WAL +
  `synchronous=NORMAL`. Schema: `log_entry(id, ts_ms, level,
  session_id, user_name, host, source, event_type, message, ref_guid,
  ref_meta_id, details)` + indexes on ts, level, ref_guid.
  Monthly rotation inside `WriteBatch` based on first entry's ts.
  Uses **raw `BEGIN`/`COMMIT`/`ROLLBACK`** through `RunQuery` instead
  of `ibDatabaseLayer::BeginTransaction` — the wrapper called
  `ibConnectionPool::SetActiveTxConnection(shared_from_this())` which
  pushed our private SQLite into `m_entries` of the main pool, so
  `ses_query` started handing it back to FB-flavoured callers
  ("no such table: Document1058" symptom).
* `loggerWriter.{h,cpp}` — single drain thread per sink. Batches up to
  256 entries or 100ms timeout. Final drain in `Run()`'s tail before
  thread exits.
* `loggerReader.{h,cpp}` — `ibLogFilter` (date range, level,
  user_name, source, event_type, ref_guid, search, limit/offset) +
  `ibLogRow`. `Query()` pre-filters files by `oes_YYYY_MM` name, opens
  each, runs prepared statement with dynamic WHERE. Sort: `ts_ms DESC,
  id DESC`.
* `loggerSweep.{h,cpp}` — `RunOnce(dir, retentionDays)`. Parses month
  from filename, deletes files (+ `.olg-wal` / `.olg-shm` sidecars)
  whose month bucket ends before cutoff.
* `logger.{h,cpp}` — `ibLogger` facade. `Info/Warn/Error/Audit`
  surface; three `Audit` overloads (no details / ibValue details /
  refGuid+refMetaId). `IsEnabled(level)` gate skipped for `Audit`
  (business events never silenced). `StartDailySweep(retentionDays)`
  kicks a background thread that runs sweep + waits 24h on a CV.

### Wiring (`appData.{h,cpp}`)

* `ibApplicationData` gained `m_logger : unique_ptr<ibLogger>`,
  `static GetLogger()`, the `ibLog` macro, `ResolveLogDir()` and
  `CreateLogger()`. Log dir: `<basedir>/oeslog` for file-mode,
  `%LOCALAPPDATA%\OES\<db>\logs` for server-mode (DB name sanitised
  for path separators).
* `CreateFileAppDataEnv` and `CreateServerAppDataEnv` call
  `s_instance->CreateLogger()` after the connection pool is up.
* `~ibApplicationData` resets `m_logger` first (before
  `m_sessionRegistry->Stop()`) — writer thread joins while sessions
  are still resolvable for the final session.closed audit row.
* Default retention 90 days, hard-coded for now (config wiring is a
  Phase-5b TODO).

## Adjacent fixes (outside logger scope but unblocked it)

### 1. `ibDataViewIndexListModel::GetFirstFetch` bridge

After the paged-fetch refactor, `BuildListHelper`/`BuildTreeHelper`
inside `ibDataViewCtrl` started calling `model->GetFirstFetch(...)`
instead of `model->GetChildren(...)`. The base class's default
`GetFirstFetch` returns 0, so any control backed by
`ibDataViewIndexListModel` (userList, my journal viewer, others)
rendered empty even when `Reset(N)` populated `m_hash`.

`dataview.h` — added a thin override that delegates to `GetChildren`:

```cpp
virtual unsigned int GetFirstFetch(const ibDataViewItem& parent,
    const ibDataViewItem& /*anchor*/, int /*count*/,
    ibDataViewItemArray& out) const wxOVERRIDE
{
    return GetChildren(parent, out);
}
```

### 2. `ibDataViewCtrl::m_viewMode` default → `ibDataViewList`

Default was `ibDataViewTree`. `BuildTreeHelper` opens with
`if (!item.IsContainer()) return;` — the invalid root item from
`BuildTree`'s initial call is non-container for flat lists, so the
top-level fetch never ran. Switched the default to `ibDataViewList`
so legacy callers (which never explicitly `SetViewMode`) get the
correct routing. Callers that need tree semantics flip via
`SetViewMode` after construction.

`datavgen.cpp` line ~3953.

### 3. `ibFirebirdMaintenanceScheduler::Stop` — std::async → CV

Stop's "join with timeout via `std::async`" pattern crashed on DLL
detach with `INVALID_PARAMETER c000000d` inside `CreateThreadpoolWork`
— Windows TPP is torn down before atexit handlers run, so spawning
new threads from atexit-driven `std::atexit([](){
ibFirebirdMaintenanceScheduler::Stop(); })` no longer works.

Replaced the futures-based timed join with a `std::condition_variable`
+ `bool workerDone` set by the worker right before returning. Stop
`wait_for`s on the CV — no new thread needed, safe at DllMain
detach time. If timeout fires, detach as before.

### 4. `ibUserInfo::Read` chunk hardening

* `FillFromRow` — each chunk read wrapped in `try { ... } catch (...) {}`
  individually. A malformed chunk (e.g. role for a deleted metadata
  object) no longer takes down the whole sys_user read; identity stays
  populated from row columns, affected chunk fields stay default.
* `ReadPasswordChunk` / `ReadLanguageChunk` — read into locals first,
  commit to `info` only after all reads succeed. Atomic-on-success
  prevents the half-populated-then-throw state that previously left
  `m_strUserPassword` set to a corrupted blob string — which made
  Verify fail for users created with empty password.
* `ReadRoleChunk` — per-role try/break; one bad role doesn't kill
  subsequent ones.

### 5. `ibSession::Open` — pin `this` while showing auth dialog

```cpp
{
    ibSessionScope scope(this);
    dlgOk = OnShowAuthenticate(user, password);
}
```

The dialog's OK handler calls `appData->Login → InstallUser`, which
uses `ibSession::Current()` to choose the target. Without the scope,
Current() resolved to nullptr / wrong session on the main thread →
`m_userInfo` stayed empty → `submitAttach` line 579 went with blank
creds → second pass through `ProcessAttach` returned "invalid user
or password" even though the dialog showed success.

Scope ensures InstallUser writes to `this`, and the subsequent
submitAttach reads the freshly-set m_userInfo.

## Decisions to remember

* **Logger has its own SQLite connection outside the main pool** —
  must use raw `BEGIN/COMMIT/ROLLBACK` via `RunQuery`, never
  `ibDatabaseLayer::BeginTransaction`. The wrapper auto-pins the
  layer to the active holder via `SetActiveTxConnection`, polluting
  the main pool's `m_entries` and causing `ses_query` to hand out
  the SQLite layer to FB-flavoured callers.
* **`ref_meta_id == 0` is the sys_user convention** — viewer drills
  via `ibDialogUserItem` keyed by guid, not `ibValueReferenceDataObject`
  (which needs a real metadata object).
* **Audit at `CommitWriteScope` covers all mutable-ref leaves** —
  Catalog, Document, ChartOfAccounts, ChartOfCharacteristicTypes
  share the scaffold; one site = four kinds. Per-leaf overrides
  (Document.Posting via WriteObject(wm,pm)) layer extra events on top.
* **`m_propertyObjectModule` lives only on leaf metaobjects** — base
  `ibValueMetaObjectRecordDataMutableRef` ctor can't reach it. Common-
  hook `SetDefaultProcedure` calls live in each leaf's own ctor.
* **`ibDataViewCtrl` default view mode = `ibDataViewList`** —
  changing the default unblocked flat-list dialogs (userList,
  auditLog, others) after the paged-fetch refactor.
* **DLL atexit cannot spawn threads** — `std::async` /
  `CreateThreadpoolWork` fail with INVALID_PARAMETER because Windows
  TPP is torn down before atexit handlers run. Use CV + worker-set
  flag for timed shutdown waits.
